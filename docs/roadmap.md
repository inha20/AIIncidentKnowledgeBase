# 로드맵

현재(v0.1)는 파일 기반 CLI 입니다. 아래는 프로젝트로 키우기 위한 단계입니다.

## v0.2 — 팀이 쓰기 편하게
- [ ] 웹 UI(조회·검색·등록 폼) — 비개발 직군도 사용
- [ ] 등록 시 민감정보 자동 감지(전화번호, 주민번호, 이메일 패턴) 후 경고
- [ ] 유사 오류 중복 감지 (등록 전 "비슷한 사례 3건" 제시)
- [ ] 슬랙/팀즈 알림 (critical 등록, 주간 리포트)

## v0.3 — 학습하는 조직
- [ ] 수정 프롬프트 재시험 하네스: 실패 입력을 회귀 테스트로 저장하고 모델/버전 변경 시 재실행
- [ ] 반복 오류 → "프롬프트 가이드" 자동 후보 생성
- [ ] 분류 자동 제안(LLM이 category/severity 를 제안, 사람이 확정)

## v0.4 — 측정
- [ ] 지표: 평균 해결 시간, 재발률(같은 category/tag), 프롬프트 수정 후 성공률
- [ ] 모델·부서별 대시보드

## v1.0 — 연동
- [ ] CompanyToAI 연동: `context-missing`/`outdated-info` 오류가 발생하면 인수인계 폴더 갱신 작업을 자동 생성
- [ ] 이슈 트래커(Jira/GitHub Issues) 양방향 동기화
- [ ] 권한·감사 로그

## 열린 질문
- 오류 레코드의 최소 필수 항목은 무엇인가 (등록 장벽 vs 분석 가능성)
- 분류 체계는 조직마다 달라야 하는가, 공통 표준이 가능한가
- 프롬프트 수정의 "해결" 은 몇 번의 재시험으로 확인하는가
