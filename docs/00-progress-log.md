# 진행 기록

AI(Claude)가 작성한 초안이며 사람의 검토 전이다.

이 기록은 2026-11-08에 시작했다. 그 전에 만든 도구(`src/`), 기록 템플릿(`templates/`), 예시(`examples/`), 시험(`tests/`), 분류·워크플로·로드맵 문서(`docs/taxonomy.md`, `docs/workflow.md`, `docs/roadmap.md`)는 이 기록이 만든 것이 아니다. README 본문은 바꾸지 않고 연구 상태 안내, 현재 상태 표, 문서 링크만 더했다. `docs/taxonomy.md`는 깨진 링크 하나를 고치고 한계 절을 더했다.

## 작업 방식

- 이 저장소에는 지금까지 **효과 측정이나 연구 결과가 없다.** 있는 것은 파일 기반 CLI, 템플릿, 분류 체계, 워크플로 문서, 로드맵, 예시 3건이다. 효과(같은 실수의 반복 감소, 해결 시간 단축)는 시험하지 않은 설계상의 기대다.
- 이 저장소는 연구가 아니라 **도구**로 다룬다(AI의 제안이며 사람이 정한다, P1). 그래서 선행연구 위치 잡기(G4)와 연구 설계를 따로 하지 않았다. 새롭다는 주장을 하지 않는다. 비슷한 오류 기록 도구나 분류 체계가 이미 있을 수 있으나 찾아보지 않았다.
- 모델을 호출하고 결과를 평가할 방법이 없다(사용자 답변, 2026-11-08 03:13 KST). 이 저장소를 도구로 다루는 동안에는 필요하지 않다.
- 이 작업은 같은 방법을 쓰는 다른 저장소(DeadlockConditionRedefinitionAndPrevention)의 연구 상태에 이 프로젝트를 맞추는 일의 한 단계다. 배경은 그 저장소의 진행 기록 중 "다른 프로젝트 세 개의 평가(2026-11-08)"에 있다. 순서는 MLFQ, Deadlock의 RQ6 결정서, 회사 인수인계 키트, 이 저장소다.
- 이 기록은 문헌을 인용하지 않는다. 확인 수준은 **V**만 쓴다. V는 이 저장소의 코드나 파일로 다시 확인한 것이며 문헌 근거와 종류가 다르고 증명이 아니다. 확인한 대상과 범위를 함께 적는다.

## 발견한 것(고치지 않음)

- **분류가 겹친다.** 예시 INC-0001은 근거 문서를 주지 않아 생긴 환각이다. 분류는 hallucination인데 원인은 context-missing으로도 읽힌다. `docs/taxonomy.md`의 두 분류 모두 '흔한 수정 방향'에 문서(맥락) 제공이 있다. 분류 팁('가장 먼저 고칠 수 있는 것')만으로는 둘 중 하나를 고르는 기준이 되지 않는다(V: 문서와 예시 읽기).
- **두 저장소의 예시 날짜가 서로 맞지 않는다.** 예시 INC-0003('입금은 D+2'였는데 10월부터 D+3, 인수인계 문서의 현재 상황 파일이 9월 기준이라고 추정)과 회사 인수인계 키트의 예시 폴더(9월 말 변경, 정확한 적용일은 미확인, 02번은 10월 1일에 갱신)는 둘 다 정산 주기 D+2→D+3을 다뤄 같은 가상 사건처럼 보이지만 날짜와 원인 추정이 다르다. 이번 단계에서는 바꾸지 않았다(P3).

## 회사 인수인계 키트(CompanyToAI)와의 연결 후보

분류 체계와 [CompanyToAI의 설계 초안](https://github.com/inha20/CompanyContextHandoverKit/blob/main/docs/02-design-draft.md)(§4 지표)이 같은 오류를 서로 다른 이름으로 부른다. 대응 후보는 아래와 같다. AI의 설계 관찰이며 구현하지 않았고 검증하지 않았다.

| PromptSolution 분류 | CompanyToAI 설계 초안의 지표 | 메모 |
|---|---|---|
| hallucination | M4 환각률 | 폴더에 답이 없는 질문에서 확정적으로 답한 비율 |
| over-refusal | M5 과잉 거절률 | 답할 수 있는 질문에서 '문서에 없음' 등으로 피한 비율 |
| outdated-info | M6 낡음 오답률, M7 최신 선택률 | 낡은 값으로 답함, 충돌에서 최신 값을 고르지 못함 |
| instruction-ignored | M2 규칙 위반율 | 폴더의 04번 규칙을 어김 |
| unsafe-output | M2의 일부 | 04번의 개인정보 마스킹 규칙 위반만 해당 |
| inconsistency | M8 일관성 | 같은 문항을 새 세션에서 반복해 답이 달라짐 |
| context-missing | 직접 대응하는 지표 없음 | |
| format-violation, reasoning-error, tool-misuse | 대응 없음 | |

- 일대일 대응이 아니다. 같은 사건이 두 분류에 걸릴 수 있다(예: 폴더에 없는 사실을 지어낸 답은 M4에서는 환각이고 이 저장소의 분류에서는 context-missing으로도 읽힌다).
- 로드맵 v1.0의 'context-missing/outdated-info 발생 시 인수인계 폴더 갱신 작업 자동 생성'에서 갱신 내용까지 AI가 제안하게 한다면, 그 정확도는 CompanyToAI 설계 초안의 Q4가 묻는 것이며 아직 시험되지 않았다. 지금은 자동화의 근거가 없다.
